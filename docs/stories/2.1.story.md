# Story 2.1: File Upload Interface for Data Extractor

## Status
Done

## Story
**As a** user,  
**I want** to upload master and data spreadsheets for extraction,  
**so that** I can provide the source data for matching operations.

## Acceptance Criteria
1. Wizard step 1 displays dual file upload areas labeled "Master Spreadsheet" and "Data Spreadsheet"
2. Drag-and-drop functionality with visual feedback for file hover states
3. File format validation accepts .xlsx, .xls, and .csv files only
4. File size validation prevents uploads over 50MB with clear error message
5. Progress indicator shows wizard step 1 of 5 as active
6. "Next" button enabled only when both files successfully uploaded
7. Clear error messages for invalid file types or sizes
8. Privacy messaging visible: "Files processed locally - never uploaded to servers"

### File Processing Architecture
[Source: architecture/core-workflows.md, architecture/frontend-architecture.md]

**JavaScript Interop Pattern:**
```elm
-- Port definitions to extend in Ports.elm

    { fileId : String

    }

    }
```

**File Processing Workflow:**
1. User drags/selects file → Upload component
2. File validation (type, size) in Elm layer
3. Valid file sent to JavaScript via port
4. SheetJS processes file and returns parsed data
5. Parsed data stored in ExtractorModel as FileData
6. Wizard navigation enabled when both files uploaded

```elm
type ExtractorRoute  
    = ExtractorStep ExtractorStep

-- Route validation for wizard step access
validateRoute : Route -> Model -> Route
validateRoute requestedRoute model =
    case requestedRoute of
        DataExtractor (ExtractorStep step) ->
            if canNavigateToStep step model.extractorState then
                requestedRoute
            else
                DataExtractor (ExtractorStep ExtractorUpload)
```

### Error Handling Integration
[Source: docs/stories/1.5.story.md Dev Notes]

**Error Types to Handle:**
```elm
-- Extend existing AppError from Story 1.5
type AppError
    = FileParseError String
    | FileSizeError Int Int -- actual size, max size
    | FileTypeError String  -- unsupported file type
    | NetworkError NetworkDetails
    | ValidationError ValidationDetails
    | BrowserCompatibilityError String
    | UnexpectedError String
```

**Error Recovery Actions:**
- File size errors → Show size limit and suggestions
- File type errors → Show supported formats (.xlsx, .xls, .csv)
- Parse errors → Allow user to retry with different file
- All errors integrate with existing ErrorDisplay component

**Detailed Error Recovery Workflows:**
1. **File Type Error Recovery**:
   - Display error: "Invalid file type. Please select .xlsx, .xls, or .csv files only"
   - Show file type icons for supported formats
   - Clear error when user selects valid file type
   - Keep other upload area unaffected if only one file is invalid

2. **File Size Error Recovery**:
   - Display error: "File size (X.X MB) exceeds limit of 50MB"
   - Suggest file compression or data reduction techniques
   - Provide link to help documentation for large file handling
   - Clear error when user selects smaller file

3. **File Parse Error Recovery**:
   - Display error: "Unable to read file. File may be corrupted or password-protected"
   - Suggest trying different file format or removing password protection
   - Allow immediate retry with same or different file
   - Log parse error details for debugging without exposing to user

4. **Drag-and-Drop Error Recovery**:
   - Handle multiple files dropped → Show "Please drop one file per area" message
   - Handle invalid drag targets → Visual feedback shows no-drop cursor
   - Handle browser compatibility issues → Fallback to file dialog
   - Clear visual feedback states when drag operation ends
