# Story 2.3: Preview Extraction Results

## Status
Done

## Story
**As a** user,  
**I want** to see sample matches before selecting output fields,  
**so that** I can verify the matching logic and understand what data is available.

## Acceptance Criteria
1. Wizard step 3 displays up to 3 sample matched records
2. Each sample shows master record with corresponding matched data record
3. Clear visual indication of which fields were used for matching
4. "No matches found" message if no records match with helpful suggestions
5. Match confidence or fuzzy match explanation displayed where applicable
6. "Re-configure" option to return to previous steps if matches look incorrect
7. All available fields from both spreadsheets visible in preview
8. Progress indicator shows step 3 of 5 as active
9. Preview generation completes within 500ms for files under 10MB
10. Memory usage remains under 100MB during preview processing

**Core Workflow Integration:**
```elm
-- Preview step in Data Extractor workflow
type PreviewMsg
    = GeneratePreview
    | PreviewGenerated ProcessedData
    | PreviewFailed String
    | ReturnToConfigure

-- Preview generation function using exact Engine interface
generatePreviewData : ExtractorModel -> Cmd PreviewMsg
generatePreviewData model =
    case (model.masterFile, model.dataFile, model.matchConfig) of
        (Just masterFile, Just dataFile, Just config) ->
            -- Use Engine.matchRows with exact interface from architecture/components.md
            let
                processedData = 
                    Engine.matchRows config masterFile.rows dataFile.rows
                        |> limitToPreviewSize 3
            in
            Task.succeed (PreviewGenerated processedData)
                |> Task.perform identity

        _ ->
            Task.succeed (PreviewFailed "Missing required data for preview")
                |> Task.perform identity
```

**Sample Display Pattern:**
```elm
-- Display matched records with field highlighting
viewMatchedRecord : List String -> List String -> MatchedRecord -> Html msg
viewMatchedRecord masterHeaders dataHeaders record =
    div [ class "matched-record" ]
        [ div [ class "master-record" ]
            [ h4 [] [ text "Master Record" ]
            , viewRecordFields masterHeaders record.masterRow record.matchedOn
            ]
        , div [ class "match-arrow" ] [ text "↔" ]
        , div [ class "data-record" ]
            [ h4 [] [ text "Data Record" ]
            , viewRecordFields dataHeaders record.dataRow record.matchedOn
            ]
        , div [ class "match-confidence" ]
            [ text ("Match Score: " ++ String.fromFloat record.matchScore) ]
        ]

-- Highlight matched fields visually
viewRecordFields : List String -> List String -> List String -> Html msg
viewRecordFields headers values matchedFields =
    List.map2 (\header value ->
        let
            isMatched = List.member header matchedFields
            fieldClass = if isMatched then "field field--matched" else "field"
        in
        div [ class fieldClass ]
            [ strong [] [ text (header ++ ": ") ]
            , text value
            ]
    ) headers values
        |> div [ class "record-fields" ]
```

## User Stories & UX Workflows for E2E Testing

### AC1: Sample Records Display (Up to 3)
**User Story:** As a user who has configured matching criteria in step 2, when I proceed to the preview step, I want to see up to 3 sample matched records so I can verify my matching configuration works as expected.

**UX Workflow:**
1. **Given:** User has completed steps 1-2 with master.xlsx (Name, ID, Email) and data.xlsx (Full Name, Employee ID, Department, Salary) with matching configured on Name ↔ Full Name, ID ↔ Employee ID
2. **When:** User clicks "Next" from Configure step
3. **Then:** Page displays "Preview Extraction Results" heading
4. **And:** Progress bar shows step 3 of 5 as active
5. **And:** Maximum of 3 sample matched records are displayed
6. **And:** Each sample shows both master and data record information
7. **When:** Dataset has 50+ matches available
8. **Then:** Only first 3 matches are shown for performance
9. **And:** No indication of total matches count (reserved for later steps)

### AC2: Master and Data Record Pairing
**User Story:** As a user reviewing preview matches, I want to see each master record paired with its corresponding matched data record so I can understand which records are being linked together.

**UX Workflow:**
1. **Given:** Preview step displays sample matches
2. **Then:** Each sample displays as a paired set with clear separation
3. **And:** Master record section shows: "Master Record" heading with all master fields (Name: "John Smith", ID: "12345", Email: "john@company.com")
4. **And:** Data record section shows: "Matched Record" heading with all data fields (Full Name: "John Smith", Employee ID: "12345", Department: "Engineering", Salary: "$75000")
5. **And:** Visual connection between master and data records (arrows, lines, or side-by-side layout)
6. **When:** Records have many fields (8+ columns)
7. **Then:** Layout remains readable with appropriate spacing and formatting
8. **And:** Long field values are handled gracefully (truncation or wrapping)

### AC3: Matched Field Highlighting
**User Story:** As a user, I want to clearly see which specific fields were used for matching so I understand how the matching logic determined these records go together.

**UX Workflow:**
1. **Given:** Preview displays matched record pairs
2. **Then:** Fields used for matching are visually highlighted (background color, bold text, or border)
3. **And:** Master "Name" and Data "Full Name" both have matching field styling
4. **And:** Master "ID" and Data "Employee ID" both have matching field styling
5. **And:** Non-matching fields (Email, Department, Salary) have normal styling
6. **When:** User configured 3 matching fields
7. **Then:** All 3 pairs of matching fields are consistently highlighted
8. **And:** Highlighting is accessible (sufficient color contrast, not color-only indication)
9. **When:** User hovers over highlighted field
10. **Then:** Tooltip or additional context shows: "Used for matching" or similar explanation

**User Story:** As a user whose matching criteria found no matches, I want clear messaging and helpful suggestions so I understand why no matches occurred and how I can improve my results.

**UX Workflow:**

4. **And:** Helpful suggestions appear: "Try the following to improve matches:"
5. **And:** Suggestion 1: "Check that selected columns contain similar data types"

7. **And:** Suggestion 3: "Review your column selections in the previous step"
8. **And:** "Re-configure" button is prominently available

10. **Then:** Specific suggestion to "Try enabling fuzzy matching for more flexible text matching"
11. **When:** No suggestions apply to current configuration

**User Story:** As a user with fuzzy matching enabled, I want to see confidence scores and explanations so I understand how certain the system is about each match and can judge the quality.

**UX Workflow:**

3. **Then:** Each matched pair shows confidence score: "Match Confidence: 92%" or similar

6. **Then:** Confidence shows actual score: "Match Confidence: 87%"

8. **When:** Multiple fields contribute to matching

10. **And:** Specific explanation: "Name: 95% match, ID: 100% match → Overall: 97.5%"
11. **When:** Confidence is below threshold but still matched
