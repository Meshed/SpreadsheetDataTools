### Coding Standards
[Source: architecture/coding-standards.md]

**Critical Rules for This Story:**
- **Pure Functions First:** All routing logic must be pure functions
- **Type Safety First:** Define custom Route types instead of using Strings
- **Module Organization:** Page components go in Pages/ directory
- **Single Responsibility:** Each route handling function should have one clear purpose
- **Immutable State Updates:** Never modify existing route state - always return new state

**Naming Conventions:**
- Modules: PascalCase (Pages.Home, Pages.NotFound)
- Functions: camelCase (parseUrl, routeToString, updateRoute)
- Types: PascalCase (Route, AppError)

## E2E Testing Scenarios

### User Stories and UX Workflows for Acceptance Criteria

#### AC1: MVU Architecture Verification
**User Story:** As a developer, I want to verify the Elm MVU architecture is properly established so that the application follows predictable state management patterns.

**UX Workflow:**
1. Open browser to application URL (http://localhost:8080)
2. Open browser DevTools and navigate to Console
3. Verify application loads without Elm compilation errors
4. Check that URL changes trigger model updates (observe in Elm debugger if enabled)
5. Verify view updates reflect model state changes
6. Test that messages are properly handled through update function
7. **Expected Result:** Clean MVU pattern with no console errors, state changes reflected in UI

**Test Data:** Basic navigation between different routes to trigger model updates

#### AC2: URL-Based Routing Implementation
**User Story:** As a user, I want URL changes to navigate between different pages so that I can bookmark and share specific sections of the application.

**UX Workflow:**
1. Start at application homepage (/)
2. Manually change URL in browser address bar to /data-extractor
3. Verify page content changes to reflect data extractor section
4. Change URL to /data-merger
5. Verify page content changes to reflect data merger section
6. Change URL back to / (or /home)
7. Verify homepage content is displayed
8. **Expected Result:** Each URL change immediately updates the page content without full page refresh

**Test Data:**
- URLs: `/`, `/home`, `/data-extractor`, `/data-merger`
- Expected page identifiers: unique text or elements for each route

#### AC3: Navigation Structure Support
**User Story:** As a user, I want to navigate using links within the application so that I can move between tools and homepage without manually typing URLs.

**UX Workflow:**
1. Load homepage (/)
2. Identify navigation elements (links, buttons) for:
   - Home/Homepage navigation
   - Data Extractor tool access
   - Data Merger tool access
3. Click navigation element for Data Extractor
4. Verify URL changes to /data-extractor
5. Verify page content displays Data Extractor placeholder
6. Click navigation element for Data Merger
7. Verify URL changes to /data-merger
8. Verify page content displays Data Merger placeholder
9. Click navigation element for Home
10. Verify URL changes to / and homepage is displayed
11. **Expected Result:** All navigation links work correctly and update both URL and page content

**Test Data:** Navigation elements with data-testid attributes for reliable selection

#### AC4: Browser Back/Forward Button Integration
**User Story:** As a user, I want browser back/forward buttons to work with the application routing so that I can navigate using familiar browser controls.

**UX Workflow:**
1. Start at homepage (/)
2. Navigate to /data-extractor (via link or URL change)
3. Navigate to /data-merger (via link or URL change)
4. Click browser Back button
5. Verify URL returns to /data-extractor
6. Verify page content shows Data Extractor
7. Click browser Back button again
8. Verify URL returns to /
9. Verify homepage content is displayed
10. Click browser Forward button
11. Verify URL changes to /data-extractor
12. Verify Data Extractor content is displayed
13. Click browser Forward button again
14. Verify URL changes to /data-merger
15. Verify Data Merger content is displayed
16. **Expected Result:** Browser navigation controls work seamlessly with application routing

**Test Data:** Navigation history: / → /data-extractor → /data-merger

#### AC5: 404 Error Handling and Homepage Redirect
**User Story:** As a user, I want invalid URLs to redirect me to the homepage so that I never encounter broken pages and always have a way to continue using the application.

**UX Workflow:**
1. Navigate to invalid URL: `/invalid-route`
2. Verify application doesn't crash or show blank page
3. Verify URL redirects to / (homepage) OR shows 404 page with navigation back to home
4. Try another invalid URL: `/data-extractor/invalid-subpage`
5. Verify same redirect/error handling behavior
6. Try completely nonsensical URL: `/xyz123/abc/def`
7. Verify consistent error handling
8. From error state, verify navigation back to valid routes works
9. **Expected Result:** All invalid URLs gracefully handled with user-friendly navigation back to homepage

**Test Data:**
- Invalid URLs: `/invalid-route`, `/data-extractor/invalid`, `/xyz123/abc/def`, `/tools/nonexistent`
- Expected behavior: redirect to `/` or display 404 page with home navigation

#### AC6: Application Error Boundary and Recovery
**User Story:** As a user, I want the application to handle errors gracefully so that temporary issues don't break my entire session and I can continue working.

**UX Workflow:**
1. Load application successfully
2. Navigate between valid routes to establish working state
3. Simulate error conditions (if possible through developer actions):
   - Force JavaScript error in browser console (if it affects Elm runtime)
   - Navigate rapidly between routes to test race conditions
   - Use browser DevTools to modify DOM and test error recovery
4. If error occurs, verify:
   - Application doesn't crash completely (blank screen)
   - Error message is user-friendly (not technical stack traces)
   - User can recover by navigating to valid routes
   - Error state doesn't persist across navigation
5. Test error recovery:
   - Navigate to homepage after error
   - Verify normal functionality resumes
6. **Expected Result:** Application handles errors gracefully with recovery mechanisms

**Test Data:** Error scenarios might include simulated network issues or DOM manipulation

### E2E Test Automation Scripts

For Cypress automation, these workflows can be converted to:

```javascript
// cypress/e2e/story-1-2-routing-navigation.cy.js
describe('Story 1.2: Basic Application Shell and Routing', () => {
  
  beforeEach(() => {
    cy.visit('http://localhost:8080')
  })

  describe('AC1: MVU Architecture', () => {
    it('loads application with proper Elm MVU pattern', () => {
      // Verify no console errors
      cy.window().its('console').then((console) => {
        cy.stub(console, 'error').as('consoleError')
      })
      
      cy.get('@consoleError').should('not.have.been.called')
      
      // Verify basic MVU functionality through navigation
      cy.get('[data-testid="nav-data-extractor"]').click()
      cy.url().should('include', '/data-extractor')
    })
  })

  describe('AC2: URL-Based Routing', () => {
    it('navigates correctly when URLs are changed manually', () => {
      // Test direct URL navigation
      cy.visit('http://localhost:8080/data-extractor')
      cy.get('[data-testid="data-extractor-page"]').should('be.visible')
      
      cy.visit('http://localhost:8080/data-merger')
      cy.get('[data-testid="data-merger-page"]').should('be.visible')
      
      cy.visit('http://localhost:8080/')
      cy.get('[data-testid="homepage"]').should('be.visible')
    })
  })

  describe('AC3: Navigation Structure', () => {
    it('provides working navigation links between all routes', () => {
      // Test navigation from homepage
      cy.get('[data-testid="nav-data-extractor"]').click()
      cy.url().should('include', '/data-extractor')
      cy.get('[data-testid="data-extractor-page"]').should('be.visible')
      
      cy.get('[data-testid="nav-data-merger"]').click()
      cy.url().should('include', '/data-merger')
      cy.get('[data-testid="data-merger-page"]').should('be.visible')
      
      cy.get('[data-testid="nav-home"]').click()
      cy.url().should('eq', 'http://localhost:8080/')
      cy.get('[data-testid="homepage"]').should('be.visible')
    })
  })

  describe('AC4: Browser Navigation Controls', () => {
    it('supports browser back and forward buttons', () => {
      // Create navigation history
      cy.get('[data-testid="nav-data-extractor"]').click()
      cy.url().should('include', '/data-extractor')
      
      cy.get('[data-testid="nav-data-merger"]').click()
      cy.url().should('include', '/data-merger')
      
      // Test browser back
      cy.go('back')
      cy.url().should('include', '/data-extractor')
      cy.get('[data-testid="data-extractor-page"]').should('be.visible')
      
      cy.go('back')
      cy.url().should('eq', 'http://localhost:8080/')
      cy.get('[data-testid="homepage"]').should('be.visible')
      
      // Test browser forward
      cy.go('forward')
      cy.url().should('include', '/data-extractor')
      cy.get('[data-testid="data-extractor-page"]').should('be.visible')
    })
  })

  describe('AC5: 404 Error Handling', () => {
    it('handles invalid routes gracefully', () => {
      // Test various invalid routes
      cy.visit('http://localhost:8080/invalid-route', { failOnStatusCode: false })
      
      // Should either redirect to home or show 404 with navigation
      cy.url().should('satisfy', (url) => {
        return url === 'http://localhost:8080/' || 
               url.includes('/not-found') ||
               url.includes('/invalid-route')
      })
      
      // Ensure user can navigate back to valid content
      cy.get('[data-testid="nav-home"], [data-testid="error-home-link"]')
        .first()
        .click()
      cy.get('[data-testid="homepage"]').should('be.visible')
    })
  })

  describe('AC6: Error Boundary Handling', () => {
    it('recovers gracefully from application errors', () => {
      // Navigate to establish working state
      cy.get('[data-testid="nav-data-extractor"]').click()
      cy.get('[data-testid="data-extractor-page"]').should('be.visible')
      
      // Rapid navigation to test race conditions
      for (let i = 0; i < 5; i++) {
        cy.get('[data-testid="nav-data-merger"]').click({ force: true })
        cy.get('[data-testid="nav-data-extractor"]').click({ force: true })
      }
      
      // Verify application still responds
      cy.get('[data-testid="nav-home"]').click()
      cy.get('[data-testid="homepage"]').should('be.visible')
      
      // Verify no unhandled JavaScript errors
      cy.window().its('console').then((console) => {
        cy.stub(console, 'error').as('consoleError')
      })
      cy.get('@consoleError').should('not.have.been.called')
    })
  })
})
```

- `[data-testid="data-merger-page"]` - Data Merger page identifier
- `[data-testid="nav-home"]` - Home navigation link
