## E2E Testing Scenarios

### User Stories and UX Workflows for Acceptance Criteria

#### AC1: Clean, Professional Landing Page Layout with Platform Branding
**User Story:** As a first-time visitor, I want to see a clean, professional homepage that clearly identifies the platform and its purpose so that I understand what tools are available and trust the application.

**UX Workflow:**
1. Navigate to application homepage (/)
2. Verify page loads without errors or broken elements
3. Check that page title displays "Spreadsheet Data Tools" prominently
4. Verify subtitle/description explains the platform's purpose
5. Confirm overall visual hierarchy is clear and professional
6. Check that page layout is clean without visual clutter
7. Verify branding is consistent and professional-looking
8. **Expected Result:** Homepage displays clean, branded layout that immediately communicates platform purpose and builds user confidence

**Test Data:** Visual elements with clear hierarchy and professional typography

#### AC2: Two Tool Cards Displayed - "Data Extractor" and "Data Merger"
**User Story:** As a user looking for data processing tools, I want to see exactly two tool options clearly displayed so that I can easily identify the available functionality without confusion.

**UX Workflow:**
1. Load homepage (/)
2. Identify tool cards section on the page
3. Count the number of tool cards displayed
4. Verify first tool card displays "Data Extractor" title
5. Verify second tool card displays "Data Merger" title
6. Check that both cards are visually distinct and properly formatted
7. Verify no additional or fewer tool cards are shown
8. Confirm cards are prominently displayed in main content area
9. **Expected Result:** Exactly two tool cards are visible with correct titles "Data Extractor" and "Data Merger"

**Test Data:**
- Expected card titles: "Data Extractor", "Data Merger"
- Card count: exactly 2 cards
- Card identifiers: `[data-testid="tool-card-data-extractor"]`, `[data-testid="tool-card-data-merger"]`

#### AC3: Each Card Shows Tool Icon, Title, Brief Description, and "Launch Tool" Button
**User Story:** As a user evaluating which tool to use, I want each tool card to show an icon, clear title, helpful description, and obvious launch button so that I can understand what each tool does and easily start using it.

**UX Workflow:**
1. Navigate to homepage (/)
2. Locate the first tool card (Data Extractor)
3. Verify tool card contains a visual icon
4. Verify tool card displays the tool title prominently
5. Verify tool card includes a brief description of functionality
6. Verify tool card has a clearly labeled "Launch Tool" button
7. Repeat verification process for second tool card (Data Merger)
8. Check that all four elements (icon, title, description, button) are visually organized and readable
9. Verify descriptions are helpful and accurately describe tool functionality
10. **Expected Result:** Both tool cards contain all four required elements with clear, helpful content

**Test Data:**
- Required elements per card: icon, title, description, launch button
- Expected descriptions should explain tool functionality briefly
- Button text: "Launch Tool" or similar clear call-to-action

#### AC4: Cards Use Modern Design (Rounded Corners, Subtle Shadows, Hover Effects)
**User Story:** As a user interacting with the interface, I want the tool cards to have modern, polished visual design with interactive feedback so that the application feels professional and responsive to my actions.

**UX Workflow:**
1. Load homepage and locate tool cards
2. Visually inspect cards for rounded corners (modern design element)
3. Check for subtle shadows around cards (depth/modern design)
4. Hover mouse over first tool card
5. Verify hover effect occurs (color change, shadow change, scale, etc.)
6. Move mouse away and verify card returns to normal state
7. Hover over second tool card and verify similar hover behavior
8. Test hover effects on different parts of the card (icon, title, button)
9. Verify hover effects enhance usability without being distracting
10. **Expected Result:** Cards display modern design elements and provide satisfying interactive feedback on hover

**Test Data:**
- Visual indicators: rounded corners, shadows
- Interactive feedback: hover state changes (detectable through CSS inspection or visual changes)

#### AC5: Responsive Grid Layout Adapts to Different Screen Sizes
**User Story:** As a user accessing the site from different devices or window sizes, I want the tool cards to automatically adjust their layout so that they remain usable and visually appealing regardless of my screen size.

**UX Workflow:**
1. Start with desktop-size browser window (1024px+)
2. Verify tool cards are displayed in appropriate grid layout
3. Resize browser window to narrower width (e.g., 800px)
4. Verify cards adjust layout automatically (may stack or resize)
5. Continue resizing to various widths (600px, 500px, 400px)
6. At each size, verify:
   - Cards remain fully visible and clickable
   - Text remains readable
   - Layout doesn't break or overflow
   - Cards maintain proper spacing
7. Resize back to larger width and verify layout returns properly
8. Test both horizontal and vertical window resizing
9. **Expected Result:** Cards adapt smoothly to different screen sizes while maintaining usability

**Test Data:**
- Test widths: 1024px, 800px, 600px, 500px, 400px
- Layout should remain functional at all tested sizes
- Grid system should be responsive and adaptive

#### AC6: Privacy Messaging Prominently Displayed Explaining Client-Side Processing
**User Story:** As a privacy-conscious user, I want to see clear messaging about how my data is handled so that I understand the application processes my files locally without uploading them to any servers.

**UX Workflow:**
1. Navigate to homepage (/)
2. Scan the page for privacy-related messaging
3. Verify privacy message is prominently displayed (not hidden or small)
4. Read the privacy message content
5. Verify message explains that processing happens client-side/locally
6. Confirm message states that no data is uploaded to servers
7. Check that message is easily readable and clear
8. Verify privacy messaging doesn't interfere with tool card functionality
9. Confirm privacy information builds user confidence rather than causing concern
10. **Expected Result:** Clear, prominent privacy message that explains local processing and reassures users about data security

**Test Data:**
- Privacy message should contain key phrases like: "client-side", "locally", "no upload", "browser", "private"
- Message should be prominently placed and easily readable
- Content should be reassuring and clear about data handling

#### AC7: Cards Navigate to Respective Tool Pages When Clicked
**User Story:** As a user ready to process my data, I want to click on a tool card and be taken directly to that tool so that I can immediately start using the functionality I selected.

**UX Workflow:**
1. Start at homepage (/)
2. Click anywhere on the Data Extractor tool card
3. Verify browser navigates to /data-extractor route
4. Verify Data Extractor tool page loads correctly
5. Navigate back to homepage (using browser back or direct navigation)
6. Click anywhere on the Data Merger tool card
7. Verify browser navigates to /data-merger route
8. Verify Data Merger tool page loads correctly
9. Test clicking different parts of each card (icon, title, description, button)
10. Verify all areas of the card are clickable and navigate properly
11. Test with keyboard navigation (tab to card, press Enter)
12. **Expected Result:** Both tool cards function as complete navigation links to their respective tool pages

**Test Data:**
- Expected navigation targets: `/data-extractor`, `/data-merger`
- All areas of cards should be clickable
- Navigation should work with both mouse and keyboard

### E2E Test Automation Scripts

For Cypress automation, these workflows can be converted to:

```javascript
// cypress/e2e/story-1-3-landing-page-tool-cards.cy.js
describe('Story 1.3: Landing Page with Tool Cards', () => {
  
  beforeEach(() => {
    cy.visit('http://localhost:8080')
  })

  describe('AC1: Professional Landing Page Layout', () => {
    it('displays clean, professional homepage with platform branding', () => {
      // Verify page loads without errors
      cy.get('[data-testid="homepage"]').should('be.visible')
      
      // Check platform title and branding
      cy.get('.homepage__title').should('contain.text', 'Spreadsheet Data Tools')
      cy.get('.homepage__subtitle').should('be.visible')
      
      // Verify professional layout structure
      cy.get('.homepage__header').should('be.visible')
      cy.get('.homepage__tools').should('be.visible')
      
      // Check overall visual hierarchy
      cy.get('.homepage__title').should('have.css', 'font-size')
      cy.get('.homepage').should('have.class', 'homepage')
    })
  })

  describe('AC2: Two Tool Cards Display', () => {
    it('shows exactly two tool cards with correct titles', () => {
      // Count tool cards
      cy.get('[data-testid^="tool-card-"]').should('have.length', 2)
      
      // Verify specific tool cards exist
      cy.get('[data-testid="tool-card-data-extractor"]').should('be.visible')
      cy.get('[data-testid="tool-card-data-merger"]').should('be.visible')
      
      // Check tool card titles
      cy.get('[data-testid="tool-card-data-extractor"]')
        .find('.tool-card__title')
        .should('contain.text', 'Data Extractor')
      
      cy.get('[data-testid="tool-card-data-merger"]')
        .find('.tool-card__title')
        .should('contain.text', 'Data Merger')
    })
  })

  describe('AC3: Tool Card Content Elements', () => {
    it('displays icon, title, description, and launch button on each card', () => {
      // Test Data Extractor card elements
      cy.get('[data-testid="tool-card-data-extractor"]').within(() => {
        cy.get('.tool-card__icon').should('be.visible')
        cy.get('.tool-card__title').should('be.visible')
        cy.get('.tool-card__description').should('be.visible')
        cy.get('.tool-card__button').should('contain.text', 'Launch Tool')
      })
      
      // Test Data Merger card elements
      cy.get('[data-testid="tool-card-data-merger"]').within(() => {
        cy.get('.tool-card__icon').should('be.visible')
        cy.get('.tool-card__title').should('be.visible')
        cy.get('.tool-card__description').should('be.visible')
        cy.get('.tool-card__button').should('contain.text', 'Launch Tool')
      })
      
      // Verify descriptions are helpful and different
      cy.get('[data-testid="tool-card-data-extractor"] .tool-card__description')
        .should('not.be.empty')
      cy.get('[data-testid="tool-card-data-merger"] .tool-card__description')
        .should('not.be.empty')
    })
  })

  describe('AC4: Modern Card Design', () => {
    it('displays cards with modern design elements and hover effects', () => {
      // Check for modern design CSS properties
      cy.get('.tool-card').should('have.css', 'border-radius').and('not.equal', '0px')
      cy.get('.tool-card').should('have.css', 'box-shadow').and('not.equal', 'none')
      
      // Test hover effects
      cy.get('[data-testid="tool-card-data-extractor"]')
        .trigger('mouseover')
        .should('have.css', 'transform')
        .and('not.equal', 'none')
      
      cy.get('[data-testid="tool-card-data-merger"]')
        .trigger('mouseover')
        .should('have.css', 'transform')
        .and('not.equal', 'none')
      
      // Verify hover state returns to normal
      cy.get('[data-testid="tool-card-data-extractor"]')
        .trigger('mouseout')
        .should('have.css', 'transform', 'none')
    })
  })

  describe('AC5: Responsive Grid Layout', () => {
    it('adapts layout for different screen sizes', () => {
      // Test desktop layout
      cy.viewport(1200, 800)
      cy.get('.homepage__tools').should('have.css', 'display', 'grid')
      cy.get('[data-testid^="tool-card-"]').should('be.visible')
      
      // Test tablet-size layout
      cy.viewport(800, 600)
      cy.get('[data-testid^="tool-card-"]').should('be.visible')
      cy.get('.tool-card').should('be.visible')
      
      // Test smaller desktop layout
      cy.viewport(600, 800)
      cy.get('[data-testid^="tool-card-"]').should('be.visible')
      
      // Verify cards remain functional
      cy.get('[data-testid="tool-card-data-extractor"]').should('be.visible')
      cy.get('[data-testid="tool-card-data-merger"]').should('be.visible')
    })
  })

  describe('AC6: Privacy Messaging', () => {
    it('displays prominent privacy message about client-side processing', () => {
      // Verify privacy banner exists
      cy.get('.privacy-banner').should('be.visible')
      
      // Check privacy message content
      cy.get('.privacy-banner').should('contain.text', 'private')
      cy.get('.privacy-banner').should('contain.text', 'local')
      cy.get('.privacy-banner').should('contain.text', 'browser')
      
      // Verify message is prominent (not tiny or hidden)
      cy.get('.privacy-banner').should('have.css', 'font-size')
        .and('not.equal', '10px') // Ensure not too small
      
      // Verify message doesn't block tool cards
      cy.get('[data-testid^="tool-card-"]').should('be.visible')
    })
  })

  describe('AC7: Card Navigation', () => {
    it('navigates to correct tool pages when cards are clicked', () => {
      // Test Data Extractor card navigation
      cy.get('[data-testid="tool-card-data-extractor"]').click()
      cy.url().should('include', '/data-extractor')
      cy.get('[data-testid="data-extractor-page"]').should('be.visible')
      
      // Navigate back and test Data Merger card
      cy.go('back')
      cy.get('[data-testid="tool-card-data-merger"]').click()
      cy.url().should('include', '/data-merger')
      cy.get('[data-testid="data-merger-page"]').should('be.visible')
      
      // Test keyboard navigation
      cy.go('back')
      cy.get('[data-testid="tool-card-data-extractor"]')
        .focus()
        .type('{enter}')
      cy.url().should('include', '/data-extractor')
    })
  })
})
```
