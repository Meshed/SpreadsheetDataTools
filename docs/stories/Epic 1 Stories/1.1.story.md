### Project Structure
[Source: architecture/unified-project-structure.md]

The project should follow this directory structure:
```
SpreadsheetDataTools/
├── src/                       # Elm application source
│   ├── Main.elm              # Application entry point and routing
│   ├── Types/                # Shared type definitions
│   ├── Shared/               # Shared modules across tools
│   ├── Tools/                # Individual tool implementations
│   ├── Pages/                # Page-level components
│   └── Ports.elm             # JavaScript interop definitions
├── assets/                   # Static assets
│   ├── styles/               # CSS files (BEM methodology)
│   ├── images/               # Image assets
│   └── fonts/                # Web fonts (if any)
├── public/                   # Public directory for serving
│   ├── index.html            # HTML template
│   ├── manifest.json         # Web app manifest
│   └── favicon.ico           # Favicon
├── tests/                    # Test files
│   ├── unit/                 # Unit tests
│   ├── integration/          # Integration tests
│   └── TestData.elm          # Shared test data
├── cypress/                  # E2E test files (future story)
├── scripts/                  # Build and development scripts
├── elm.json                 # Elm package configuration
├── package.json             # Node.js package configuration
├── webpack.config.js        # Webpack build configuration
└── README.md                # Main project documentation
```

### Technology Stack
[Source: architecture/tech-stack.md]

- **Frontend Language:** Elm 0.19.1
- **Build Tool:** Webpack 5.74.0
- **Testing:** elm-test 0.19.1
- **E2E Testing:** Cypress 10.8.0 (future story)
- **CSS Framework:** Custom CSS with BEM methodology
- **JavaScript Interop Libraries:** 
  - SheetJS (xlsx) 0.18.5 - for Excel file parsing
  - FileSaver.js 2.0.5 - for file downloads

### Coding Standards
[Source: architecture/coding-standards.md]

Critical rules to follow:
- **No Inline Styles:** All styling must be in separate CSS files using BEM methodology
- **Module Organization:** Shared functionality goes in Shared/ directory
- **Pure Functions First:** All business logic must be pure functions
- **Type Safety:** Use Elm's type system, no Debug.todo in production
- **Port Isolation:** JavaScript interop only through ports
- **Single Responsibility:** Each module should have one clear purpose

### Development Scripts
The package.json should include these scripts:
```json
{
  "scripts": {
    "dev": "webpack serve --mode development",
    "build": "webpack --mode production", 
    "test": "elm-test"
  }
}
```

### Webpack Configuration Requirements
- Must compile Elm files
- CSS processing with separate files (no inline styles)
- Development server with hot reload
- Production build optimization
- Asset handling for images and fonts

### Testing
[Source: architecture/testing-strategy.md]

**Test Organization:**
- Tests go in `tests/` directory
- Unit tests in `tests/unit/`
- Integration tests in `tests/integration/`
- Use elm-test 0.19.1 framework
- Focus on pure function testing (70% of tests should be unit tests)
- Test naming should be descriptive sentences

**Example Test Structure:**
```elm
-- tests/Example.elm
module Example exposing (..)

import Expect
import Test exposing (..)

suite : Test
suite =
    describe "Example tests"
        [ test "handles empty input gracefully" <|
            \_ ->
                Expect.equal 4 (2 + 2)
        ]
```

#### AC2: Build Scripts Verification
**User Story:** As a developer, I want to run build scripts to compile and bundle the application for development and production environments.

**UX Workflow:**
1. Open terminal in project root
2. Run `npm install` to install dependencies
3. Execute `npm run dev`:
   - Verify webpack-dev-server starts
   - Check console for compilation success
   - Note the localhost URL provided
4. Execute `npm run build`:
   - Verify dist/ folder is created
   - Check for compiled JavaScript bundles
   - Verify CSS files are generated separately
5. Execute `npm test`:

   - Check that example test passes
6. **Expected Result:** All scripts execute without errors

**Test Data:** Basic Main.elm with "Hello World" output

#### AC4: Development Server Hot Reload Testing
**User Story:** As a developer, I want the development server to automatically reload when I make changes so that I can see updates instantly.

**UX Workflow:**
1. Start development server with `npm run dev`
2. Open browser to localhost URL (typically http://localhost:8080)
3. Verify initial page loads with Elm application
4. Modify Main.elm:
   - Change text content (e.g., "Hello World" to "Hello Elm")
   - Save the file
5. Observe browser:
   - Page should auto-refresh OR
   - Content should update without full page reload
6. Check terminal for recompilation messages
7. **Expected Result:** Changes appear in browser within 2-3 seconds

**Test Data:** 
```elm
-- Initial Main.elm content
view : Model -> Html Msg
view model =
    div [] [ text "Hello World" ]

-- Modified content for testing
view : Model -> Html Msg  
view model =
    div [] [ text "Hello Elm" ]
```

#### AC5: HTML Template Verification
**User Story:** As a security engineer, I want to verify the HTML template includes proper security headers and meta tags for a secure web application.

**UX Workflow:**
1. Open public/index.html in editor
2. Verify meta tags present:
   - `<meta charset="UTF-8">`
   - `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
   - CSP meta tag with appropriate policies
3. Check manifest.json reference:
   - `<link rel="manifest" href="/manifest.json">`
4. Start dev server and open browser DevTools
5. Inspect page source to verify:
   - Meta tags are rendered
   - CSP headers are active (check Network tab)
   - No inline scripts or styles
6. **Expected Result:** All security headers and meta tags properly configured

**Test Data:** Sample CSP policy:
```html
<meta http-equiv="Content-Security-Policy" 
      content="default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';">
```

#### AC6: Test Framework Execution
**User Story:** As a QA engineer, I want to run unit tests to verify the testing framework is properly configured and functional.

**UX Workflow:**
1. Navigate to project root in terminal
2. Run `npm test` or `elm-test`
3. Observe test output:
   - Test runner starts successfully
   - Example test file is discovered
   - Test execution shows pass/fail status
4. Create new test file tests/SampleTest.elm:
   - Add simple arithmetic test
   - Save file
5. Run tests again:
   - Verify new test is discovered
   - Check both tests execute
6. Intentionally fail a test:
   - Modify assertion to fail
   - Run tests to verify failure reporting
7. **Expected Result:** Test framework discovers, runs, and reports test results accurately

**Test Data:**
```elm
-- tests/SampleTest.elm
module SampleTest exposing (..)

import Expect
import Test exposing (..)

suite : Test
suite =
    describe "Sample arithmetic tests"
        [ test "addition works correctly" <|
            \_ ->
                Expect.equal 5 (2 + 3)
        , test "multiplication works correctly" <|
            \_ ->
                Expect.equal 6 (2 * 3)
        ]
```
